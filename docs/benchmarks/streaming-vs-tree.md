# Streaming versus the tree path

Since [#57], `from_str` deserialises every target except `Value` straight from
parser events, instead of composing a `Node` graph first. `Value` keeps the tree
path deliberately — it *is* a tree, so streaming into one would build the same
graph anyway.

This page is generated by `mise run bench:compare`. The numbers are not typed by
hand.

## How to read it

`significant` is the column that decides, and it is `faster` or `slower` only
when the two confidence intervals do **not** overlap. A speedup of 1.03× between
two noisy measurements is not a result, and is reported as `no`.

That distinction is not pedantry. On 2026-08-01 a degraded host produced 77
internally consistent measurements that were 4.6×–20.9× wrong in absolute terms;
every arm was slow together, so nothing inside the data looked wrong.
`mise run bench:compare` refuses to start on a host above 30% load per core for
that reason.

## Cases

- **generic** — an owned recursive value. The document is fully materialised
  either way, so this isolates the cost of the intermediate `Node` graph.
- **partial** — a struct naming two fields. The tree path builds every node
  before the target discards most of them; streaming walks the events and drops
  what nothing asked for.

The `Statistic` column names which estimate the comparison used. Criterion's
headline figure is the **slope** — a regression over iteration counts, far less
sensitive to the occasional long iteration a busy host produces. It is absent
for slow benchmarks, where one iteration per sample leaves no line to fit, and
the **mean** serves there instead. The two are never mixed within a pair.
